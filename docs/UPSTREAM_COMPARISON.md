# 上游对比与改动归因

本仓库为南京理工大学江阴校区 Combat 战队的自瞄调试仿真适配：Windows / RTX 5070 Ti 运行仿真，Linux 主机运行自瞄。自瞄算法将由另一独立仓库发布；这里记录仿真端与上游的关系。

## 对比基准

- 公开上游：Blackjack200/bevy_robomaster_simulator。
- 本次读取的上游 master：`43681255bc5415cdc15797d54fe7478062af42ed`（2026-09-03，license）。
- 本机原工程没有 `.git`；无法证明它最初下载自哪一个 commit。历史中 2025-11 月存在相近的单体布局和 Bevy 0.17.2 版本，但多个提交共享相同文件，不能把“最相似”当作精确分叉点。
- 可靠的本机增量基准：`src_backup_20261009_233316`；它已包含较早的 ROS 控制和 UDP 真值等适配，不是纯上游版本。

因此，下表分别描述上游既有能力、本机已落地改造和本次发布整理，不把所有本机文件都归因于本次工作。当前上游功能较本机分支丰富，两者不是简单的“全面升级”关系。

## 能力与结构

| 方面 | 上游当前 master | 本机发布分支 |
|---|---|---|
| 目标 | 多目标 RoboMaster 仿真、ROS/Talos 等 | 战队 ROS 图像/自瞄闭环、小陀螺实验 |
| 引擎 | 后续架构已演进，见上游 Cargo.toml | 保留本机 Bevy 0.17.2 / Avian3D 0.4 |
| 源码组织 | scene/systems/config、多个 crates 等 | 原单体 main + ros2 + power_rune，新增 spin/shotlog |
| 资源布局 | 根目录 assets，多个机器人/战场模型 | src/assets，5 个编译嵌入资源 |
| 云台接口 | 当前说明含 armor_solver/Talos | rune_solver/cmd_gimbal，固定本机消息定义 |
| 场景覆盖 | 原仓库已提供能量机关、装甲板和视角控制等 | 继承相关功能，默认聚焦固定位置旋转步兵 |
| 数据集 | 历史路线持续变化 | 保留角点诊断和 writer 类；未完成自动写出流程 |

## 本机已落地改动

| 文件 / 模块 | 实际行为与用途 | 证据及边界 |
|---|---|---|
| src/spin.rs | 5 种旋转模式、可配置参数、f64 积分、固定随机种子 | 新增 1069 行；19 个既有单元测试；slow 7.5 由启动配置覆盖 |
| src/main.rs | 固定敌方 XZ、出生点固定/按键解除、运动写入 Transform 与物理 Rotation | 避免初始场景漂移；实际运动更新顺序以源码为准 |
| src/ros2/plugin.rs | GimbalCmd 桥接、坐标变换、板中心计算、UDP 快照、采集配置 | 命令度→弧度；板中心取 mesh 顶点质心，不取会重合的节点原点 |
| src/ros2/gt_udp.rs | 独立 JSON 真值，含云台、中心、4 板、spin 状态 | 不污染自瞄 ROS 真值话题；需要明确时钟与坐标 |
| src/statistic.rs + main.rs | 总命中和近侧命中并列，定期 HITSTAT | near 为命中时板面朝炮口，不能直接视为真机准确率 |
| main.rs 装甲板变换 | 15° 内倾作用于 AM 父节点；修复支点为 t_am+t_p+c | 使板、灯条和编号一起变换，修复 AM3/4 安装错位 |
| main.rs 装甲板尺寸 | 当前代理面归一到 137.80×59.84 mm | 135×56 mm 尺寸尝试已回滚；仍与算法 135.7×56 模型有差异 |
| main.rs 发射/控制 | 冷却 0.05 s；云台限速 6 rad/s；弹丸寿命 2 s；碰撞过滤调整 | 20 发/s 是上限，不保证实际发射率；2 s 不适合长滞空弹道 |
| src/shotlog.rs | req/launch/hit/miss 事件和 shot_id、近侧标记 | SHOT_LOG 门控，不改开火决策；存在 NaN 和重复碰撞等解析边界 |
| ros2/capture.rs、topic.rs | CAM 仪表：回读/编码/发送失败等诊断 | 有助区分采集和 DDS 发送问题，不代表已经解决 GPU 回读瓶颈 |
| src/util/image.rs | 环境变量 JPEG 质量配置 | 发布配置 q100；JPEG 仍为有损编码 |
| FastDDS XML | maxMessageSize=1400；8 MB socket buffer；保留旧文件名 | 避免大 RTPS UDP 数据报引起严重 IP 分片；不设 NIC 白名单 |

相对 2026-10-09 快照，本次逐字节比较发现 **9 个不同/新增 `.rs` 文件**（含新增 spin/shotlog）。`src/ros2.rs` 的 UDP 模块声明在该快照中已存在，所以不计入这个增量；它可能出现在其他日期的同步清单中。增量见 [patch](evidence/changes-since-20261009.patch)，该文本供阅读，不作为承诺字节还原的回滚工具；精确版本以 Git commit 和 [SHA256](evidence/source-sha256.json) 为准。

## 已回滚、未实施和外部改动

- **FOV 环境变量：未落地。** 当前 plugin.rs 中垂直 FOV 仍是 45°。不能根据带 fov_env 的备份名声称已实现。
- **135×56 mm 装甲板：已回滚。** 当前尺寸是 137.80×59.84 mm，不能沿用备份目录名作判断。
- `/camera_info` 自动喂给外部算法：仿真会发布，但当时 sp_vision_25 从 YAML 取内参，未订阅该话题。改分辨率需要算法端同步。
- Linux 侧显示去白边/缩放、pose 开火门、25 s 预热门、高度分组尝试：属于外部 C++ 算法改动，**没有打包为本仓库仿真功能**。
- 早期“残余 miss 不可区分”“far-hit 是固定物理上限”等说法曾被 10-14 的时钟对齐复核质疑。没有可靠校时与完整样本，不复用这些结论，也不把旧蒙特卡洛模型当成验收依据。
- 本次没有访问、修改或重启 Linux 主机，没有移植真机入口，也没有引入新的自瞄算法。

## 本次发布整理

1. 保留本机所有活跃 `.rs` 和 5 个嵌入资源，SHA256 一致；将 Cargo 工程放在根目录，与上游根目录 Cargo 的习惯一致。
2. 纳入本机实际使用的 rm_interfaces 消息/服务源文件；补齐 `std_msgs` 的 package.xml/CMake 声明，按上游保留 Apache-2.0 许可证。
3. 保存 Cargo.lock、Rust 工具链、现有 Pixi manifest/lock 和官方 ROS 包 URL/SHA256。
4. 新入口采用配置覆盖与自动 MSVC 检测，去除启动时强杀进程、必须先有 exe 才允许编译、固定本机路径等限制。
5. Git 仅包含可维护源码/资源；已编译程序和原生依赖放 Release。默认真值目标改为 loopback，日志级别抑制高频 SIM_GT 刷屏，原本机工程不变。
6. 工具默认路径改为仓库相对路径；新增环境、测试、证据和协作说明，未上传记忆文件及历史远程登录脚本。
